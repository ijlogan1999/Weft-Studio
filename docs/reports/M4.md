# Milestone 4 report: the arrange window

## What works

- **The window.** Weft Studio now opens to the arrange window instead of the placeholder:
  - control bar with panel toggles, transport, an editable position / tempo / signature display, count-in, snap and grid, follow, keyboard MIDI, theme switch and CPU meter;
  - ruler with bar numbers that follow the signature map and thin out when zoomed out, a cycle strip (drag to set, click to toggle), punch range, and a marker lane (click jumps, double-click adds or renames, drag moves on the grid, right-click deletes);
  - track headers with name, number, colour, mute, solo and record enable; double-click renames (Esc cancels, an empty name reverts); the lower edge resizes (24 to 400 px), Ctrl+Shift+wheel resizes all;
  - inspector with the selected region (name, mute, loop, gain, fade lengths and curves) and track (name, colour, monitoring);
  - editors area with the audio editor; the mixer and piano roll are labelled placeholders;
  - side panel with a file browser (folders plus supported audio and MIDI files; click previews, drag imports) and the project media list with durations and usage counts; Comments, Chat and History are placeholders;
  - status bar, menus that show each command's shortcut, tooltips with name and shortcut on every control, and dark and light themes that switch without a restart. Panel layout and theme are saved per user.
- **Region editing in the tracks area.** Click, Shift+click, rubber band and Ctrl+A selection; drag to move across tracks (below the last track makes a new one), Ctrl+drag copies, Alt bypasses snap, Esc cancels, each drag one undo step. Corner handles trim, fade and loop (D-UI-4). Waveform and note overviews, loop repeats, muted regions desaturated and labelled, take folders show "Take n/m" and switch on click. The empty project says how to start.
- **Tools** from the T menu: pointer, pencil (a one-bar MIDI region on an instrument track), scissors, glue, eraser, mute; Esc returns to the pointer.
- **Arrange commands** (from the earlier M4 commits): snap with smart, bar, beat, note and triplet grids (D-ARR-5); move, nudge, copy, paste, repeat, split, join (with a rendered file when needed), delete, mute, loop, gain, fades with three curves, and equal-power crossfades (D-ARCH-23); markers with previous, next and numbered jumps; zoom around the pointer and Z to fit the selection or the project (D-UI-6).
- **Audio editor.** Double-clicking an audio region shows its whole source with the used part highlighted. The edges trim to the exact sample at any zoom, down to 16 px per sample (D-UI-5), with snap following the arrange grid.
- **Import.** Drag WAV, AIFF, FLAC, MP3 or MIDI files onto the tracks area or from the browser. Audio is converted to the project rate and stored by hash; MIDI files make instrument tracks, and an empty project takes the file's tempo (D-AT-1). Files that can't be read are named in one message.
- **File preview** plays through the engine after the master fader at the device rate.

## Stubbed or not yet in the window

- Mixer and piano roll are placeholders until their milestones; Comments, Chat and History wait for collaboration.
- Track delete and duplicate exist as commands (tested in M3) but have no menu or context menu yet.
- No region gain line in the tracks area (gain is set in the inspector), and take folders switch takes but don't expand into lanes.
- The audio editor draws from the 256-frame peak cache, so at extreme zoom the waveform is a block envelope rather than individual samples. Trimming is still exact.
- The Preferences, Project Settings, Bounce and Audio Setup dialogs aren't built yet.

## Known issues

- AT-UI-3 (display scaling) needs real Windows hardware and wasn't run.
- On Linux the [UI] tests need `xvfb-run`; CI installs it. A debug build logs one harmless JUCE assertion per rename test, because the test window is never put on screen.
- Windows UI tests run only on the Windows CI runner; nothing here was clicked through by hand on Windows.
