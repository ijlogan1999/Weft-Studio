# Milestone 2 report: audio engine and transport

## What works

- **Snapshot render graph.** On every model change the message thread compiles an immutable `EngineSnapshot`:
  - per-track audio segments, with regions on top hiding the ones underneath (D-W3-2);
  - region gain, fades (linear, equal power, S-curve) and region loops;
  - track volume and mute, and master volume;
  - MIDI notes scheduled at sample positions, with region transpose, velocity offset and play-time quantize;
  - the tempo and signature maps at the device rate, and the cycle range.
- **Snapshot handoff (ARCHITECTURE §3).**
  - The audio thread picks up a new snapshot through an atomic pointer swap.
  - Old snapshots are freed on the message thread once the audio thread has acknowledged a newer one. The audio thread never allocates or frees.
  - Instruments live in a slot table outside snapshots, so they keep their state (and their held notes) across edits.
- **Transport.**
  - Play, stop, return to start on stop (on or off), and locate.
  - Cycle wraps with no gap, including a cycle shorter than one buffer.
  - Record with a count-in of 0, 1 or 2 bars. The count-in can run into negative time before bar 1. The recorded input starts exactly at the record position.
  - Record with nothing armed just plays and says "No tracks armed".
  - Tempo and signature edits from the transport display, Go to Start / End, comma and period by bar, and U (cycle to selection).
- **Metronome.** The click sounds are synthesized, not samples. Bar starts get a higher pitch at the same level. Beats follow the signature's denominator, so 6/8 clicks every eighth note. The level is in dB, and the click can sound during record, play or both.
- **Position displays.** Bars and beats (`2.1.2.0`) and time (`0:00:02.125`), plus parsing typed positions (`5 3`, `0:30`).
- **CPU meter and dropout counter.** Load is shown as a share of the buffer period. A block that overruns its period counts as a dropout, and so do xruns the driver reports.
- **Devices.**
  - `JuceAudioDevice` wraps JUCE's driver layer: WASAPI shared (the default) and exclusive, and ASIO when built with the SDK (D-ARCH-14). JUCE types stay inside the implementation.
  - `NullDevice` drives all engine tests.
  - The engine handles block sizes from 1 to the maximum, changes of buffer size and sample rate, and a device rate that differs from the project's (playback is resampled and recording is refused, D-W0-1).
- **`weft-cli render <project> <out.wav>`** plays a saved project through the engine into a WAV file. `--from`, `--seconds` and `--metronome` are optional.
- **WAV reading and writing** (PCM 16/24/32 and float, including WAVE_FORMAT_EXTENSIBLE) in core.

## Decisions recorded

D-ARCH-12 to D-ARCH-16 in `docs/ARCHITECTURE.md` §9:
- D-ARCH-12: media plays from memory until M3.
- D-ARCH-13: the count-in is click-only and always clicks.
- D-ARCH-14: ASIO is built only when the SDK path is given.
- D-ARCH-15: cubic interpolation for a sample-rate mismatch, for now.
- D-ARCH-16: the engine counts in device samples, and cycle doesn't wrap while recording until M3.

## Stubbed or not started

- **Not tested here:**
  - AT-TRN-3 and AT-TRN-18 (Space key focus, follow-playhead scrolling) are [UI] tests and come with the arrange window in M4.
  - The JUCE device test skips when there is no audio hardware, which is the case in the container and probably on CI runners. Real WASAPI and ASIO runs are [HW] tests.
- **Recording** captures device input into a preallocated buffer and hands it back on stop. Turning it into regions, per-track inputs, the WAV writer thread and latency compensation are M3.
- **No pan, buses, sends or plug-ins in the engine yet.** Every track plays straight to the master, and mono sources play on both channels at unity. All of these are M6.
- **AT-TRN-17** uses a test instrument that burns 80% of each block, standing in for the fixture plug-in until plug-in hosting (M6).
- **AT-RT-1** counts allocations and frees (operator new/delete replaced in the test program) and Weft's own blocking calls. Plug-in hosting, automation and the wrapped-mutex check join it as those features arrive.
- **Snapshots are rebuilt whole** on each change. Sharing unchanged tracks between snapshots is left for AT-RT-2 (M13), when 10,000 edits during playback make it matter.
- **Weft Keys** (the built-in instrument) is M3. Instrument tracks play only when an instrument is set in the rack.

## Known issues

- **AT-TRN-17 is timing-based.** It measures real time on the machine running the tests, so a heavily loaded CI runner could push the reading above 90%. CTest runs it serially in CI.
- **The ASIO driver isn't built in CI** because the SDK isn't fetched (D-ARCH-14). It needs a decision on how release builds get the SDK.
- **The app doesn't use the engine yet.** JUCE modules are compiled into the device library privately, so linking it into the app needs one shared JUCE library first. That is done in M4, when the app gets its transport.
